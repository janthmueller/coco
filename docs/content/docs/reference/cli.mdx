---
title: Command reference
description: The CoCo commands available in the current preview.
---

Run `coco --help` or `coco COMMAND --help` for the exact options in your build.

| Command                            | Purpose                                             |
| ---------------------------------- | --------------------------------------------------- |
| `coco repo add [path]`             | Add a Git repository to CoCo                        |
| `coco repo list`                   | List added repositories                             |
| `coco create <name> …`             | Prepare a separate worktree and conversation        |
| `coco ls`                          | List workspaces in the selected repository          |
| `coco status <workspace>`          | Show one workspace's current state                  |
| `coco status <workspace> --follow` | Follow a workspace until it pauses or becomes ready |
| `coco send <workspace> <message>`  | Start the first or next turn                        |
| `coco jump <workspace>`            | Open the workspace in the Codex terminal UI         |
| `coco decide <decision-id>`        | Answer a pending approval or question               |
| `coco diff <workspace>`            | Show changes made in the workspace                  |
| `coco mcp serve …`                 | Expose CoCo to an MCP host                          |

## Create a workspace

```bash
coco create <name> \
  [--base <git-ref>] \
  [--profile <name>] \
  [-s, --send <message>] \
  [-j, --jump]
```

Names contain lowercase letters, numbers, and hyphens, with optional slashes
between components, such as `fix/login`. `--base` defaults to `HEAD`. The
repository must be clean. Without `--send`, creating a workspace does not start
a turn.

## Choose a repository

Workspace commands use the repository containing your current directory. A
leading path selects another added repository:

```bash
coco ../api ls
coco ../api status fix/login
```

Use `coco --all-repos ls` (short: `coco -a ls`) for a combined list.
`--all-repos` also lets
`status`, `send`, `jump`, and `diff` resolve a name that is unique across all
added repositories. Full workspace IDs always resolve globally.

## Machine-readable output

Use `--json` with repository or workspace listing and inspection:

```bash
coco repo list --json
coco ls --json
coco status feat/first --json
```

`status --follow` is human-oriented and cannot be combined with `--json`.

## Answer a request

When `status` shows that Codex is waiting, it also prints a decision ID. Open
the request and choose from its numbered options:

```bash
coco decide <decision-id>
```

Decision IDs work from any directory and do not take a repository path or
`--all-repos`. Secret answers are hidden while you type and are not retained by
CoCo.

## MCP

```bash
coco mcp serve --repository /absolute/path/to/project
coco mcp serve --repository /absolute/path/to/project --allow-send
```

See [Use CoCo through MCP](../../guides/mcp/) before enabling `--allow-send`.
