Run `coco --help` or `coco COMMAND --help` for the options in your installed
version.

## Installed commands

| Command    | Purpose                                                  |
| ---------- | -------------------------------------------------------- |
| `coco`     | Create, inspect, and control workspaces                  |
| `cocod`    | Keep CoCo and its Codex work available between CLI calls |
| `coco-mcp` | Expose repository-scoped workspace tools to an MCP host  |

Start `cocod` before using either of the other commands.

## Command shape

```text
coco [OPTIONS] [REPOSITORY_PATH] <COMMAND>
```

Workspace commands use the repository containing the current directory by
default. Put a registered path before the command to select another
repository:

```bash
coco ../api ls
coco ../api status fix/login
```

Use `--all-repos` or `-a` with `ls`, `status`, `send`, `jump`, or `diff` to
list across repositories or resolve a globally unique name:

```bash
coco --all-repos ls
coco -a jump fix/login
```

`create` always needs one repository. `repo`, `models`, `decide`, and `mcp`
do not accept the leading path or `--all-repos`. A full workspace ID resolves
globally without either option.

## Repository commands

```text
coco repo add [PATH]
coco repo list [--json]
```

`repo add` registers the Git repository containing `PATH`; it defaults to `.`
and is safe to repeat. `repo list` shows every registered repository.

## Model command

```text
coco models [--json]
```

Lists the models reported by the running Codex installation. This command is
not repository-scoped.

## Create a workspace

```text
coco [REPOSITORY_PATH] create <NAME>
  [--base <GIT_REF>]
  [--fork-from <WORKSPACE>]
  [--compact]
  [--profile <NAME>]
  [-m, --model <MODEL>]
  [-s, --send <MESSAGE>]
  [-j, --jump]
```

`--base` defaults to `HEAD`. Names are 1–63 bytes and contain lowercase ASCII
letters, numbers, and hyphens, with optional single slashes between
components, such as `fix/login`. Each component begins and ends with a letter
or number. The normal creation path requires a clean checkout.

Use `--fork-from` instead of `--base` to create from a ready, clean workspace
in the same repository. `--compact` is available only with `--fork-from`.

`--send` starts the first turn after creation. `--jump` then opens the same
thread in the Codex terminal UI. Their short forms are independent and may be
combined.

## Workspace commands

In the forms below, `<WORKSPACE>` may be a repository-local name or full ID.

| Command                            | Purpose                                           |
| ---------------------------------- | ------------------------------------------------- |
| `coco ls [--json]`                 | List workspaces in the selected scope             |
| `coco status <WORKSPACE> [--json]` | Show current state and pending input              |
| `coco status <WORKSPACE> --follow` | Follow activity until it stops or needs you       |
| `coco send <WORKSPACE> <MESSAGE>`  | Start the first or next turn                      |
| `coco jump <WORKSPACE>`            | Open the existing thread in the Codex TUI         |
| `coco diff <WORKSPACE>`            | Print a bounded tracked patch and untracked paths |

`status --follow` cannot be combined with `--json`. Quote messages containing
spaces. `send` returns after Codex accepts the turn; use `status --follow` to
watch it.

## Answer a request

```text
coco decide <DECISION_ID>
```

When CoCo can present a pending approval or question, `status` prints its
decision ID. `decide` shows numbered choices and may accept text for an
ordinary question. Secret answers are hidden while you type and are not
retained by CoCo.

Decision IDs work from any directory and do not accept a repository path or
`--all-repos`.

## Machine-readable output

```bash
coco repo list --json
coco models --json
coco ls --json
coco status feat/first --json
```

These commands emit one JSON value to standard output. Human-oriented follow
mode is intentionally excluded.

## MCP commands

```text
coco mcp serve --repository <PATH> [--allow-send]
coco-mcp --repository <PATH> [--allow-send]
```

Both forms expose the same repository-scoped standard input/output server.
See [Use CoCo through MCP](../../guides/mcp/) before enabling `--allow-send`.
