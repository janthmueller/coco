CoCo stands for **Codex Coordinator**. It keeps parallel Codex conversations
attached to the Git checkout and settings where each piece of work belongs.

Use it when you want to leave one piece of Codex work running, move to
something else, and return later without guessing which conversation changed
which files.

## What CoCo does

CoCo adds durable, named workspaces around Codex. It can:

- prepare several separate pieces of work before starting any model turns;
- start Codex work, wait for its response, and follow its state from short
  terminal commands;
- surface approvals and questions that need your answer;
- reopen the same conversation in the Codex terminal UI;
- close and later restore a workspace without deleting its branch or thread;
- retire a closed workspace with separate choices for its branch and thread;
- and find workspaces across several registered repositories.

Codex still performs the actual reasoning, tool calls, and file changes, and
raises approval requests for you to decide. CoCo keeps their surrounding
context together.

## What is a workspace?

A workspace is one unit of Codex work. It contains:

- a registered repository;
- a separate Git worktree, normally on a `coco/<name>` branch;
- one persistent Codex thread after work begins; and
- its selected model and Codex profile.

The code base, conversation context, and Git branch binding are separate
choices. A workspace can start from another commit, inherit an existing Codex
conversation, use an existing branch, or run detached without coupling those
decisions.

The worktree prevents changes from being mixed into your current checkout.
The first `send` or interactive `jump` creates the thread. After that, `send`,
`status`, and `jump` all continue the same conversation instead of starting
unrelated sessions.

## How the workflow fits together

| You want to…                                 | Use…                          |
| -------------------------------------------- | ----------------------------- |
| Prepare work in a separate checkout          | `coco create`                 |
| Start or continue a Codex turn               | `coco send`                   |
| Check once or follow live activity           | `coco status`                 |
| Answer an approval or question               | `coco decide`                 |
| Enter the existing Codex terminal UI         | `coco jump`                   |
| Review tracked changes and untracked paths   | `coco diff`                   |
| Free a worktree without losing its workspace | `coco close`                  |
| Restore or permanently retire closed work    | `coco reopen` / `coco delete` |

The `coco` command normally exits after each operation. Add `--wait` to `send`
to print that turn's final response. Keep `cocod` running while you use CoCo so
ongoing work remains available to later commands. `status` reports state only;
leaving `status --follow` or the terminal UI does not by itself cancel an
active turn.

For automation, `coco-mcp` can expose a repository-scoped view of the same
workspaces to an MCP host. Its default tools are read-only.

<Callout type="warn" title="Alpha software">
  CoCo is intended for supervised local use on Linux and macOS. Read the
  [troubleshooting and limitations](/docs/reference/current-limitations) before
  relying on it for important or unattended work.
</Callout>
