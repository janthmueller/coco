---
title: Use CoCo through MCP
description: Let an MCP-capable application inspect or continue workspaces in one repository.
---

CoCo includes an MCP server for applications that should work with the same
workspaces as the CLI. Start `cocod`, then configure your MCP host to launch:

```bash
coco-mcp --repository /absolute/path/to/project
```

The equivalent command is:

```bash
coco mcp serve --repository /absolute/path/to/project
```

The repository is fixed when the server starts. By default it offers only
read-only tools:

| Tool                | What it does                            |
| ------------------- | --------------------------------------- |
| `workspaces.list`   | List workspaces in the repository       |
| `workspaces.status` | Show the current state of one workspace |
| `workspaces.diff`   | Show changes made by one workspace      |

## Allow messages

Add `--allow-send` only when the MCP host should be allowed to start another
Codex turn:

```bash
coco-mcp --repository /absolute/path/to/project --allow-send
```

This adds `workspaces.send`. Any connected MCP host can then start the first or
a later turn for a ready workspace, so keep the option disabled unless you need
it.

This MCP server controls CoCo workspaces. Selecting which MCP servers are
available inside an individual Codex workspace is not supported yet.
