---
title: Models and profiles
description: Choose a model or reuse a named set of Codex settings.
---

Choose a model for one workspace with `--model`. Use a profile when you want to
reuse several Codex settings together, such as reasoning effort, sandbox, or
approval policy.

## See available models

With `cocod` running, list the models offered by your Codex installation:

```bash
coco models
```

Use the value in the `MODEL` column when creating a workspace:

```bash
coco create refactor/cache --model gpt-5.6-sol
```

For scripts, `coco models --json` returns the same catalog as structured JSON.

## Define a profile

Add it to your Codex configuration file, normally `~/.codex/config.toml`:

```toml title="~/.codex/config.toml"
[profiles.dev]
model_reasoning_effort = "high"
approval_policy = "on-request"
sandbox_mode = "workspace-write"
```

Use keys supported by your installed Codex version.

## Use it for a workspace

```bash
coco create refactor/cache \
  --base main \
  --profile dev

coco send refactor/cache "Refactor the cache and run its tests"
```

Without `--profile`, CoCo uses Codex's default configuration. You can combine a
profile with `--model`; the explicit model wins while the other profile settings
still apply:

```bash
coco create refactor/cache --profile dev --model gpt-5.6-sol
```

The chosen settings apply when the workspace is created. Changing the profile
file later does not reconfigure an existing workspace.
