---
title: Models and profiles
description: Choose one model or apply a reusable Codex configuration to a workspace.
---

A **model** chooses which model runs the workspace. A **profile** is a named
Codex configuration file that can group settings such as reasoning effort,
sandbox mode, approval policy, or instructions.

## List available models

With `cocod` running, ask the connected Codex installation for its current
model catalog:

```bash
coco models
```

The output shows the value to pass as `--model`, its display name, whether it
is the default, and the reasoning efforts it advertises. For scripts, use:

```bash
coco models --json
```

## Select a model

Choose a model when you create the workspace:

```bash
coco create refactor/cache --model gpt-5.6-sol
```

Without `--model`, Codex selects the model from its normal configuration.
CoCo does not maintain a separate model catalog or alias list.

## Define a Codex profile

Named profiles use the same file convention as `codex --profile`. Create a
file next to your normal Codex configuration:

```toml title="~/.codex/dev.config.toml"
model_reasoning_effort = "high"
approval_policy = "on-request"
sandbox_mode = "workspace-write"
```

For a profile named `dev`, the filename must be `dev.config.toml` below
`$CODEX_HOME`, normally `~/.codex`. The file itself is the configuration layer;
do not wrap it in a `[profiles.dev]` table. Use keys supported by your installed
Codex version.

## Apply a profile

```bash
coco create refactor/cache \
  --base main \
  --profile dev
```

The special profile name `default` uses Codex's normal base configuration and
does not require `default.config.toml`.

## Combine a profile and model

An explicit model overrides a model named inside the profile. Every other
profile setting still applies:

```bash
coco create refactor/cache \
  --profile dev \
  --model gpt-5.6-sol
```

## Keep profile files stable

CoCo records which named profile was applied when the workspace was created.
Do not change or remove its settings while you still need the workspace: after
a `cocod` restart, CoCo refuses to resume the thread if the parsed
configuration no longer matches. Comments and formatting do not affect this
check.

When you want different settings, create another profile name and use it for a
new workspace. CoCo checks the named profile file, not Codex's base
configuration layer. If you change the base configuration, inherited settings can
therefore change for any resumed workspace the next time `cocod` starts. Put
settings that must stay fixed explicitly in the named profile.
