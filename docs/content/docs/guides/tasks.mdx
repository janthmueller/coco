---
title: Working with tasks
description: Prepare, start, follow, and enter isolated Codex work.
---

A task is one piece of work assigned to Codex. CoCo gives it a separate Git
checkout, so it can change files without touching the branch open in your main
working directory.

## Prepare a task

Run this inside a repository already added to CoCo:

```bash
coco new fix-login --base main
```

The repository must be clean. CoCo creates the branch `coco/fix-login`, its
worktree, and a Codex conversation. Preparing a task does not send a message or
start work.

## Start or continue work

`send` starts the first turn. Use it again whenever the task is ready:

```bash
coco send fix-login "Fix the login redirect and run the relevant tests"
coco send fix-login "Now add a regression test"
```

CoCo does not queue messages while a turn is still active.

## Check the current state

```bash
coco ls
coco status fix-login
coco status fix-login --follow
```

`status` reports where the task is and shows its worktree. `--follow` keeps a
spinner visible while Codex is working, then stops when the task is ready,
waiting for you, failed, or interrupted. Pressing

<kbd>Ctrl</kbd>+<kbd>C</kbd> only stops following; it does not stop the task.

## Enter the task

```bash
coco jump fix-login
```

This opens the existing Codex conversation in its managed worktree. Messages
you send there stay in the same task rather than creating a new conversation.

To inspect file changes without entering the task, run `coco diff fix-login`.

CoCo currently leaves created branches and worktrees in place. It does not
merge, delete, or clean them up automatically.
