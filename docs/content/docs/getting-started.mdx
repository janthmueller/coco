title: Quickstart
description: Start Codex work, leave the command, follow its state, and return through the native UI.
---

This walkthrough starts one Codex turn, leaves it under CoCo's control, follows
its state from another command, and then opens the same conversation in the
Codex terminal UI.

Before continuing, [install CoCo](../installation/) and keep `cocod` running in
another terminal.

## 1. Prepare a repository

Open a clean Git repository with at least one commit, then register it:

```bash
coco repo add .
```

Registration is safe to repeat. It records the repository for CoCo but does
not create a commit, branch, or worktree.

## 2. Create a workspace

```bash
coco create feat/first --base HEAD
```

CoCo creates a separate worktree and the branch `coco/feat/first`. Your current
checkout remains unchanged. The workspace is now `Prepared`: no Codex thread
or model turn exists yet.

## 3. Send the first instruction

```bash
coco send feat/first \
  "Inspect this project and propose one focused improvement"
```

This creates the persistent Codex thread and starts its first real turn. The
command returns as soon as Codex accepts the work; `cocod` keeps the workspace
available while the turn continues. Add `--wait` to the command when you want
to stay attached and print that turn's final response instead.

You can also create and send in one command:

```bash
coco create feat/second \
  --send "Review the command-line interface"
```

## 4. Check or follow state

Show every workspace in the current repository:

```bash
coco status
```

Inspect one workspace, or follow only its state changes:

```bash
coco status feat/first --follow
```

The follow command keeps the current state visible as it changes, including
when the workspace becomes ready, needs your input, or reports a problem. It
also shows the activated workspace's execution process and, on Linux, its
current resource use. It never prints conversation messages. Press `Ctrl+C` to
stop following; a Codex turn does not stop with the display.

When CoCo supports the request Codex is waiting on, `status` prints a decision
ID and the next command:

```bash
coco decide <decision-id>
```

Review the request, then move with the arrow keys and press Enter—or press the
number beside the answer you want for an immediate choice.

## 5. Enter the Codex terminal UI

```bash
coco jump feat/first
```

This opens the existing conversation inside its managed worktree. Use `/quit`
or `/exit` to leave the UI. Leaving does not cancel work that is still running;
an explicit Codex interrupt does.

## What you created

Your original checkout is still on its original branch. CoCo's worktree and
`coco/feat/first` branch remain available for review even after you leave the
UI or restart `cocod`.

Continue with [Working with workspaces](../guides/workspaces/) for status,
diffs, forks, compaction, multi-repository use, and safe workspace retirement.
