---
title: Quickstart
description: Create, start, follow, and enter your first separate Codex workspace.
---

This walkthrough starts one Codex turn in a separate Git worktree and then
opens the same conversation in the Codex terminal UI.

Before continuing, [install CoCo](../installation/) and keep `cocod` running in
another terminal.

## 1. Prepare a repository

Open a clean Git repository with at least one commit, then register it:

```bash
coco repo add .
```

Registration is safe to repeat. It records the repository for CoCo but does
not create a commit, branch, or worktree.

## 2. Create a workspace

```bash
coco create feat/first --base HEAD
```

CoCo creates a separate worktree, the branch `coco/feat/first`, and a Codex
thread. Your current checkout remains unchanged, and no model turn starts yet.

## 3. Send the first instruction

```bash
coco send feat/first \
  "Inspect this project and propose one focused improvement"
```

You can also create and send in one command:

```bash
coco create feat/second \
  --send "Review the command-line interface"
```

## 4. Follow the work

```bash
coco status feat/first --follow
```

The command updates until the workspace becomes ready, needs your input, or
reports a problem. Press <kbd>Ctrl</kbd>+<kbd>C</kbd> to stop following; the
Codex turn continues.

When CoCo supports the request Codex is waiting on, `status` prints a decision
ID and the next command:

```bash
coco decide <decision-id>
```

Review the request, then move with the arrow keys and press Enter—or press the
number beside the answer you want for an immediate choice.

## 5. Enter the Codex terminal UI

```bash
coco jump feat/first
```

This opens the existing conversation inside its managed worktree. Use `/quit`
or `/exit` to leave the UI. Leaving does not cancel work that is still running;
an explicit Codex interrupt does.

## What you created

Your original checkout is still on its original branch. CoCo's worktree and
`coco/feat/first` branch remain available for review even after you leave the
UI or restart `cocod`.

Continue with [Working with workspaces](../guides/workspaces/) for status,
diffs, forks, compaction, and multi-repository use.
