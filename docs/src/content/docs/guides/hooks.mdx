---
title: Run commands with hooks
description: Send agent updates to another tool or run a program after workspace changes.
---

A **hook** runs your program after an agent publishes a signal or a workspace
is created, closed, reopened, or deleted.

Start by saving a workspace update to a local file. You can then use the same
hook setup to send agent signals to another tool.

## Save a local update

With `cocod` running, find `tee`, the command that will save the update:

```bash
command -v tee
mkdir -p ~/.config/coco
```

Create `~/.config/coco/hooks.json`. If it already exists, add the entry to
its `hooks` array while preserving your other hooks and guards:

```json title="~/.config/coco/hooks.json"
{
  "version": 1,
  "hooks": [
    {
      "id": "record-workspace",
      "event": "workspace.created",
      "command": [
        "/absolute/path/to/tee",
        "/absolute/path/to/latest-workspace.json"
      ]
    }
  ]
}
```

Use the executable path from `command -v tee`. Set the output path to
`latest-workspace.json` in your CoCo configuration folder, using its full
absolute path. Keep it outside the worktrees your agents edit. CoCo passes
the event to `tee`, which replaces that file with the latest workspace update.

## Load and check it

```bash
chmod 600 ~/.config/coco/hooks.json
coco hook validate
coco hook reload
coco hook list
```

Inside a Git repository with at least one commit, create a workspace:

```bash
coco create try/hooks
```

Hooks run in the background. Check for a successful `record-workspace`
delivery:

```bash
coco hook history
```

Once it succeeds, read the file. Its JSON includes `workspace.name` set to
`try/hooks`:

```bash
cat ~/.config/coco/latest-workspace.json
```

Changes to `hooks.json` take effect after `hook reload` or a coordinator
restart. An invalid reload leaves the previous configuration active.

## Connect a review notification

To send agent updates to a webhook, follow [Publish agent updates](../signals/)
to enable `review.requested@1`. You also need `curl` and an HTTP endpoint that
accepts CoCo's [event JSON](../../reference/automation/#hook-input).

Find your executable with `command -v curl`, then add this entry to the
`hooks` array in the same configuration:

```json
{
  "id": "notify-review",
  "event": "signal.emitted",
  "signal": "review.requested@1",
  "command": [
    "/absolute/path/to/curl",
    "--fail", "--silent", "--show-error",
    "--header", "Content-Type: application/json",
    "--data-binary", "@-",
    "https://your-service.example/coco/review"
  ],
  "timeoutSeconds": 30,
  "maxAttempts": 3
}
```

Replace the executable path and endpoint. This sends the full event, including
the workspace and signal payload, so use an endpoint you trust with those
contents. Validate and reload the configuration:

```bash
coco hook validate
coco hook reload
```

After an agent emits `review.requested@1`, check `coco hook history` for the
delivery result and confirm that your endpoint received it.

## Run your own program

Replace the `command` array with your executable and arguments. CoCo
passes the event as JSON on standard input. Your program can use it to update
another tool, record an artifact, or decide which follow-up action to take.

A command can receive the same event again after a failure or restart. Use
the event's `id` to avoid repeating external effects, such as creating the
same ticket twice.

Hooks run as your user with only `PATH` inherited. Use absolute file paths,
configure any required credentials explicitly, and keep commands in the
foreground. Avoid actions that trigger the same hook repeatedly.

See [Automation reference](../../reference/automation/) for event names,
payloads, filters, retries, and configuration fields. To check an action
before it happens, use a [guard](../guards/).

For prompt, tool, or permission events within Codex itself, configure
[Codex's native hooks](https://learn.chatgpt.com/docs/hooks).
