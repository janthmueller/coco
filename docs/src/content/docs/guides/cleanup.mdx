---
title: Review and clean up
description: Review agent changes, free a checkout, or delete work while choosing what to keep.
---

Review the agent's work before merging it. Then close the workspace if you
want to return later, or delete it when you are done.

## Review changes

```bash
coco diff fix/login
```

This shows tracked changes since the workspace's original base, including
committed and uncommitted edits, and lists new untracked files. Large patches
may be truncated with a notice.

### Commit and bring changes back

Wait until the agent is ready and leave its Codex UI before changing files.
Find the checkout path and branch with:

```bash
coco status fix/login
```

In a separate shell, open that path and review the files and recent commits:

```bash
cd /absolute/path/to/worktree
git status --short
git log --oneline -5
git diff
git diff --cached
```

The agent may already have committed its work. If you still need to commit
changes, stage only the files you intend to include and review the staged diff:

```bash
git add path/to/changed-file
git diff --cached
git commit -m "Fix the login redirect"
```

Run your project's checks before integrating the change. For a local merge,
return to your original checkout and check that it has no uncommitted changes:

```bash
cd /absolute/path/to/project
git status --short
```

Once it is clean, a fast-forward merge into `main` looks like this. Replace
`main` with your integration branch and `fix/login` with the branch shown by
CoCo:

```bash
git switch main
git merge --ff-only fix/login
```

If the branches have diverged, use your project's normal merge, rebase, or
pull-request workflow. Keep the workspace branch until its work is retained
where you need it.

## Close work for later

```bash
coco close fix/login --dry-run
coco close fix/login
```

Closing frees the worktree and stops its execution processes. The branch
and conversation remain available.

Commit, stash, or move files you need before closing. If tracked, untracked,
or ignored files remain, an interactive close lists them and asks whether to
discard them. Press Enter to cancel and keep them. A clean close needs no
confirmation.

CoCo blocks close while work, a pending decision, an attached Codex UI, or
background commands still use the workspace.

Find and restore closed work:

```bash
coco list --closed
coco reopen fix/login
coco jump fix/login
```

Reopen restores the checkout at the retained commit. For detached work,
first preserve new commits on a branch or tag before closing.

## Delete finished work

You can delete an open or closed workspace directly:

```bash
coco delete fix/login --dry-run
coco delete fix/login
```

The default removes the workspace, its worktree, its Codex conversation, and
its CoCo-created branch. Review the plan and confirm with `y`.

### Keep the conversation or branch

```bash
coco delete fix/login --keep-thread
coco delete fix/login --keep-branch
coco delete fix/login --keep-thread --keep-branch
```

CoCo prints what it retained. Use a retained thread ID as
`coco create <name> --context <thread-id>` to copy its conversation later.
Branches selected with `--checkout` are always kept.

### Handle unsaved work

The deletion plan lists local files and commits that would lose their last
retaining branch, tag, or remote-tracking branch. Commit, move, or merge work
you want to keep, or use `--keep-branch` to retain the branch's commits.

In a terminal, deletion uses one confirmation covering the whole plan,
explicitly including any files or unretained commits it would discard.
Press Enter to cancel. Interactive close also asks before discarding files.

For scripts, `--yes` skips confirmation but never grants permission to
discard files or commits. Add `--discard-changes` for files and, on deletion,
`--discard-unretained-commits` for commits only when you intend that loss.
See the [lifecycle options](../../reference/cli/#close-reopen-and-delete)
for explicit discard flags and conversation archiving.

If cleanup is blocked or interrupted, follow
[Troubleshooting](../../reference/current-limitations/#close-or-delete-is-blocked).

## Remove a repository from CoCo

After deleting all of a repository's workspaces, remove it from CoCo's lists
and selectors:

```bash
coco repo remove .
```

This leaves the Git repository and its files untouched. `repo rm` is the short
alias. A later `repo add` or workspace creation adds the same repository again.
