---
title: Run and navigate agents
description: Start parallel work, find agents across repositories, and continue their conversations.
---

Use a named workspace for each piece of work you want an agent to handle.
Each workspace has a separate Git checkout and keeps its conversation for
you to return to.

## Start work

Inside a Git repository with at least one commit:

```bash
coco create
```

The walkthrough lets you choose the name, code and conversation starting
points, profile, model, cleanup, and what to do after creation. Press Enter to keep the
highlighted default. Existing workspaces appear when you choose one as the
conversation source. When you run it inside a reusable CoCo workspace, that
current workspace is offered directly. You can also enter an exact Codex
thread ID.

For a faster direct command, provide the name and instruction:

```bash
coco create fix/login -s "Fix the login redirect and run its tests"
coco create review/cache -s "Review the cache for correctness issues"
```

`-s` is short for `--send`. Add `-j` to open the Codex UI after sending:

```bash
coco create investigate/search -s "Investigate slow searches" -j
```

Use `coco create fix/login -i` when you already know the name but still want
the walkthrough. Any other flags you provide prefill and skip those decisions.

To prepare a workspace before giving it an instruction, use
`coco create fix/login`. Its status is `Prepared` until work begins.
The first `create` also adds that repository to CoCo.

CoCo normally starts from your current commit on a new branch named after
the workspace, such as `fix/login`. See [Choose code and context](../context/)
to select another base, reuse a conversation, or bring local changes.

## Use a temporary workspace

For a short review or exploration, request safe cleanup when you leave the
Codex UI:

```bash
coco create scratch/review --temporary -j
```

After the last open CoCo-launched UI exits normally, CoCo tries to remove the
workspace, its worktree, owned branch and conversation. Add `--keep-thread`
to keep the conversation. Leaving normally without sending a message also
attempts cleanup.
Wait for the `Removed` or `Kept` message before sending another interrupt.

To start with an existing conversation, choose a context source during creation:

```bash
coco create scratch/review --temporary -c fix/login -j
```

The source conversation remains available when the temporary workspace is removed.

You can prepare it first and open it later:

```bash
coco create scratch/later --temporary
coco jump scratch/later
```

In the walkthrough, choose **Clean up after a TUI session**. Opening Codex
becomes the highlighted next action; returning to the shell remains available.

Running work, changed files, commits that would be lost, and other deletion
safeguards can block cleanup. CoCo then keeps the workspace, explains why, and disables
automatic cleanup. Review it and use [manual cleanup](../cleanup/) when ready.
Opening another conversation in that UI also disables automatic cleanup and
keeps the workspace available.
Sending a message alone does not trigger cleanup. A failed UI start or abnormal
exit leaves the workspace available for a later session.

## See who needs attention

```bash
coco list
coco status -f
```

Both show workspaces in the current repository. `status -f` keeps the
display updated until Ctrl+C. Use `coco status fix/login` for one
workspace's details and any pending request. While an agent is working,
status may add a short live detail such as `Working · Checking tests` or
`Working · Compacting context`.

| State | What to do |
| --- | --- |
| Prepared | Send an instruction or open the Codex UI |
| Working | Let the agent continue or enter its conversation |
| Needs approval / input | Use the displayed `decide` command or `jump` |
| Ready | Review the response or send more work |
| Unloaded | Use `send` or `jump` to continue the saved conversation |
| Failed / Unavailable | Inspect the workspace details and [troubleshoot](../../reference/current-limitations/) |

Ready means the agent can accept another instruction. Review its changes
before treating the work as complete.

### Focus the overview

Bring agents needing attention to the top across repositories and hide
unloaded conversations:

```bash
coco status -af --sort state,name --exclude-state unloaded
```

Prepared workspaces stay visible. This only changes what you see; agents keep
their current state. Rows appear and disappear as their states change.
See [ordering and filters](../../reference/cli/#order-and-filter-the-overview)
to choose other sort keys or show only particular states.

## Enter and leave the conversation

```bash
coco jump fix/login
```

Use `/quit` or `/exit` to leave the Codex UI. Active work continues while
`cocod` stays running. An explicit interrupt inside Codex cancels that turn.

Run `coco jump` without a name for a selector. Navigate with arrow keys or
`j`/`k`, press Enter, or press a displayed number to choose immediately.
Recently used conversations appear first, with a dim relative time when Codex
reports one. Use `coco jump --sort name` for name order, or add `-g` to choose
across repositories. The selector shows a branch only when it differs from
the workspace name; detached worktrees remain marked `detached`. The workspace
selectors in guided creation, `send`, `diff`, `limits`, `close`, `reopen`, and
`delete` use the same ordering and time display.

### Find open terminals

```bash
coco status -a --clients
```

Add `--clients` (`-c`) to see Codex UIs opened through `coco jump` or `create -j`.
Inside tmux, their locations appear as `tmux dev:2.1`: session `dev`, window
`2`, pane `1`. Other terminals show `TUI`, and several open UIs are listed
together. CoCo detects tmux automatically; no plugin setup is needed.

Use `coco status -afc` to keep the overview updated. `—` means no
open UI was reported; the agent can still be working. Locations are recorded
when you jump, so reopen the UI after renaming or moving its tmux pane to
update its label.

## Send another instruction

When the workspace is ready:

```bash
coco send fix/login "Add a regression test"
```

The command returns after the instruction is accepted. Add `--wait` to
print the final response when it arrives. You can send from another terminal
while the Codex UI is open, provided the agent is ready.

`coco send fix/login` prompts for the message. `coco send` lets you
choose the workspace first. CoCo currently accepts one active turn per
workspace; wait for it to finish before sending the next instruction.

## Work across repositories

Point `create` at another repository without changing directories:

```bash
coco ../api create fix/login -s "Fix the login redirect"
```

CoCo adds the repository automatically. Put its path before later commands to
work there:

```bash
coco ../api jump fix/login
```

Use `coco repo add /absolute/path/to/api` when you want a repository to appear
in lists and selectors before creating a workspace. `coco repo list` shows all
currently added repositories.

For an overview of every repository, use `-a`:

```bash
coco list -a
coco status -aft
```

The tree view gives each repository its own path heading and unfolds shared
parts of names such as `frontend/login` and `frontend/search`. A unique path
stays on one line. Omit `-t` for the flat table.

For one workspace whose name you want to find globally, use `-g`:

```bash
coco jump fix/login -g
```

If that name exists in several repositories, select one with its path.
The [CLI reference](../../reference/cli/#command-shape) covers full IDs and
scope options.

## Answer a request

Inspect the workspace to see its pending request and how to respond:

```bash
coco status fix/login
```

If a decision command is available, use the displayed ID:

```bash
coco decide <decision-id>
```

Review the request and select a response. Questions may accept text; secret
answers are hidden while typing. You can also respond from the Codex UI.

For resource measurements and token counts, see [Monitor usage](../resources/).
When finished, [review and clean up the workspace](../cleanup/).
